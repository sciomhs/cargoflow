# 01 — Выжимка ТЗ «CargoFlow» и привязка к критериям

## Заказчик и боль
CargoFlow — грузоперевозки между городами Казахстана, ~35 машин, 15–30 рейсов в день.
Сейчас всё в WhatsApp и звонках: диспетчер звонит водителям («ты загрузился? где машина?»),
клиенты звонят менеджеру, документы теряются в чатах, статусы устаревают,
нет истории рейса, руководитель не видит картину.

**Формула для ролика (критерий 1):** проблема — диспетчер тратит день на звонки, клиент
не знает, где груз, документы теряются. Пользователи — диспетчер, водитель, клиент,
руководитель. Потребность — один актуальный статус рейса, видимый всем. Результат —
звонки заменяются нажатием кнопки водителем; клиент сам видит таймлайн.

## Роли (4)
1. **Диспетчер/логист** — создаёт заказ и рейс, назначает водителя и машину, видит статусы, задержки, документы, подтверждает доставку.
2. **Водитель** — видит свои рейсы, адреса и контакты, меняет статус, добавляет фото, документы, сообщает о проблеме, подтверждает передачу груза.
3. **Клиент** — видит свои заказы, статус и этапы, получает уведомления, подтверждает получение, смотрит документы.
4. **Руководитель логистики** — дашборд: рейсы, активные, задержки, завершённые, загрузка водителей.

## Обязательный функционал (14 пунктов ТЗ → что должно быть в приложении)
1. Создание заказа (`CF-1845`: клиент, груз, вес, места, точка загрузки/доставки, даты).
2. Создание рейса на основе заказа (`R-642`: водитель, авто, госномер, выезд, плановая доставка).
3. Карточка рейса для водителя — всё в одном месте.
4. Последовательные статусы перевозки (12 основных + задержка/проблема/отмена), каждое изменение с временем.
5. Работа водителя — смена статусов по шагам.
6. Фотофиксация по этапам (до загрузки / после загрузки / при доставке).
7. Документы рейса (накладная, акт, доверенность, фото с подписью).
8. Фиксация проблемы (категория, причина, комментарий, фото) → диспетчер видит отдельно.
9. Отслеживание заказа клиентом (упрощённый вид, без служебных комментариев).
10. Подтверждение доставки (получатель, время, комментарий, фото) → «Ожидает подтверждения» → клиент/диспетчер подтверждает.
11. История рейса — лог всех событий, сохраняется после завершения.
12. Главный экран диспетчера — цифры по статусам + список активных рейсов.
13. Экран водителя — только свои рейсы, быстрые действия.
14. Экран клиента, дашборд руководителя, уведомления.

## Главный сценарий защиты (критерий 4 и 10)
Диспетчер создаёт заказ → формирует рейс → назначает водителя и машину → водитель получает
рейс → принимает → фиксирует прибытие на загрузку → фото груза → «Груз загружен» →
«В пути» → клиент видит изменение → «Прибыл на выгрузку» → документы + получатель →
«Груз передан» → клиент подтверждает → рейс завершён.

**Дополнительный сценарий:** водитель в пути → «Сообщить о проблеме» → Задержка, 90 минут
→ диспетчер получает уведомление → статус «Задерживается» → у клиента новое расчётное время.
