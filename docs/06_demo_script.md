# 06 — Сценарий ролика (6 мин 30 с)

Структура по критерию 10: проблема → решение → основные функции → рабочий сценарий →
доп. возможности → ценность. Текст говорится спокойно, экран — эмулятор в светлой теме,
demo-mode включён, звук уведомлений выключен.

## 0:00–0:40 — Проблема (критерий 1)
Слайд или говорящая голова. Текст:
«CargoFlow — логистическая компания, 35 машин, до 30 рейсов в день между городами
Казахстана. Сегодня диспетчер узнаёт, где груз, звонками водителям, клиент узнаёт — звонками
диспетчеру, а накладные лежат в чатах WhatsApp. Пользователи приложения — диспетчер,
водитель, клиент и руководитель логистики. Им нужен один актуальный статус рейса, который
видят все. Приложение заменяет звонки одним нажатием кнопки водителем».

## 0:40–1:10 — Решение и структура (критерии 2, 3)
Экран входа, быстро показать 4 роли: «Одно приложение, после входа у каждой роли свой
интерфейс». Пролистать таббары диспетчера (Рейсы · Заказы · Внимание), водителя (Сегодня ·
История), клиента (Доставки · Уведомления), дашборд руководителя. «Всего двадцать два экрана».

## 1:10–4:10 — Главный сценарий (критерии 4, 5, 3)
Строго по `02_product_spec.md` §3. Все данные вводятся вживую, вслух называть, что вводим.
- Диспетчер создаёт заказ CF-1845 (30 с).
- Создаёт рейс R-642, выбирает Руслана (активных: 0) и Volvo FH (30 с).
- Войти как водитель → уведомление → открыть рейс → «Принять рейс» → «Выехал» → «Прибыл на загрузку» → «Начать загрузку» → фото → «Груз загружен» → «В пути» (60 с). По пути показать: адреса, кнопку позвонить, контакты.
- Войти как клиент → таймлайн, «В пути», следующий этап (20 с).
- Водитель: «Прибыл на выгрузку» → «Начать разгрузку» → фото при выдаче → накладная №457 → получатель Алексей Смирнов → «Груз передан» (40 с).
- Клиент: «Подтвердить получение» (10 с).
- Диспетчер: рейс в «Завершены», открыть историю событий — все отметки с временем (20 с).

## 4:10–4:50 — Дополнительный сценарий: задержка (критерии 4, 6)
На другом рейсе (R-648 Асхат Нуртаев) водитель сообщает о задержке 90 мин с фото →
диспетчер во «Внимании» сдвигает плановую доставку → клиент видит новое время.
«Приложение работает и в нестандартной ситуации, а не только в идеальной».

## 4:50–5:40 — Дополнительные возможности (критерий 8)
1. Авиарежим → два статуса у водителя → «2 действия ожидают сети» → сеть → ушли. «Водитель на трассе часто без связи».
2. Экспорт истории рейса в PDF, открыть результат.
3. Центр уведомлений клиента и переключение языка на казахский (5 с).

## 5:40–6:10 — Соответствие функций задаче и архитектура (критерии 6, 9)
Слайд «боль → функция» из `02_product_spec.md` §5. Одна фраза про архитектуру:
«React Native на Expo, данные в Supabase: Postgres, хранилище фото, realtime. Каждая смена
статуса — событие в таблице `trip_events`, из неё строится история и уведомления».

## 6:10–6:30 — Ценность и развитие
«Диспетчер перестаёт звонить, клиент перестаёт спрашивать, документы не теряются,
руководитель видит картину. Дальше — GPS, маршруты, push, интеграция с 1С».
