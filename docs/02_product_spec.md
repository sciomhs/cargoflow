# 02 — Продуктовая спецификация CargoFlow

## 1. Одно приложение, четыре роли
Одна сборка Expo. После входа роль определяет корневой навигатор. Переключение ролей в
demo-mode — через экран «Войти как…» (для ролика), в проде — по учётной записи.

## 2. Карта экранов (Nav Read — черновик, финализирует `mobile-nav-plan`)

### Диспетчер — 3 таба: Рейсы · Заказы · Внимание
```
(dispatcher)/
  trips/            список активных рейсов, сегменты: Все · Ожидают · В пути · Выгрузка · Задержка · Завершены
  trips/[id]        карточка рейса: шапка (маршрут, водитель, авто), таймлайн событий, фото, документы, проблемы, кнопка «Подтвердить доставку»
  orders/           заказы: Новые · В рейсе · Завершены
  orders/[id]       карточка заказа + кнопка «Создать рейс»
  orders/new        форма заказа (модалка полноэкранная)
  trips/new?order=  форма рейса: выбор водителя (список с загрузкой: активных рейсов), выбор авто
  attention/        exception-first: Проблемы · Задержки · Не приняты водителем · Ожидают подтверждения
  problems/[id]     карточка проблемы: причина, фото, кнопки «Принять», «Изменить плановую доставку»
```
Главный экран диспетчера = `trips/` с верхней полосой цифр: Всего · Ожидают загрузки · В пути ·
На выгрузке · Задерживаются · Завершены (как в ТЗ, §17).

### Водитель — 2 таба: Сегодня · История (без FAB)
```
(driver)/
  today/            текущий рейс крупно + следующие; быстрые действия: Открыть · Принять · Статус · Проблема · Документ
  trips/[id]        главный рабочий экран: одна большая кнопка «следующий статус», адреса с кнопкой «позвонить», контакты, груз
  trips/[id]/photo  камера/галерея с привязкой к этапу (до загрузки / после загрузки / при выдаче)
  trips/[id]/docs   документы: тип, фото, статус «Загружена»
  trips/[id]/problem  форма проблемы: категория (Задержка / Поломка / Груз / Дорога / Другое), причина, комментарий, фото, оценка задержки
  trips/[id]/handover подтверждение передачи: получатель, комментарий, фото, подпись (опционально)
  history/          завершённые рейсы
```

### Клиент — 2 таба: Доставки · Уведомления
```
(client)/
  deliveries/       Активные · Завершённые
  deliveries/[id]   таймлайн: этапы с временем, «следующий этап», плановая/новая доставка, фото, документы; кнопка «Подтвердить получение» когда статус «Ожидает подтверждения»
  notifications/    центр уведомлений
```

### Руководитель — 1 экран + детализация
```
(manager)/
  dashboard/        Рейсов за месяц · Завершено · В пути · Задерживаются · Отменено · Среднее время доставки; списки: по водителям, по направлениям, % без задержек
  drivers/[id]      рейсы водителя
```

### Общее
```
(auth)/login        вход (demo: выбор роли + «Войти»)
settings            профиль, demo-mode, язык RU/KZ, выход
```
Итого ~22 экрана, из них отдельных по ТЗ — 20+. Критерий 2 закрыт.

## 3. Главный пользовательский сценарий (ролик, ~3 минуты)
Нумерация совпадает с ТЗ §15.
1. Диспетчер: «Заказы → Новый». Вводит: ТОО «СтройКомплект», керамическая плитка, 8 500 кг, 12 паллет, Павлодар, ул. Промышленная 18 → Астана, ул. Индустриальная 42, загрузка 21 окт, доставка до 22 окт 15:00. Сохраняет → `CF-1845`, статус «Новый».
2. Диспетчер: в заказе «Создать рейс». Выбирает Руслан Касымов (активных: 0), Volvo FH 777 ABC 14, выезд 21 окт, плановая 22 окт 13:00 → `R-642`, статус «Назначен».
3. Переключение на водителя (demo-mode): уведомление «Вам назначен новый рейс».
4. Водитель открывает рейс, видит груз, адреса, контакты → «Принять рейс».
5. «Прибыл на загрузку» (09:05).
6. Фото груза в кузове → «Груз загружен» (09:40).
7. «В пути» (09:45).
8. Переключение на клиента: `CF-1845` Павлодар → Астана, «В пути», груз загружен 09:40, плановая 22 окт 13:00, следующий этап «Прибытие на выгрузку».
9. Водитель: «Прибыл на выгрузку» (14:30).
10. Фото при выдаче, документ «Накладная №457», получатель Алексей Смирнов, комментарий «Повреждений не выявлено» → «Груз передан» → статус «Ожидает подтверждения».
11. Клиент: «Подтвердить получение» → «Доставка подтверждена».
12. Рейс «Завершён». У диспетчера — в «Завершены», история событий полная.

## 4. Дополнительный сценарий — задержка (~40 секунд)
Водитель в пути → «Сообщить о проблеме» → Задержка · Закрытие дороги · «Движение ограничено,
задержка ~90 минут» · фото → отправить. Диспетчер: вкладка «Внимание», красная карточка,
нажимает «Сдвинуть плановую доставку на 90 мин» → статус рейса «Задерживается», новая
плановая 14:30. Клиент: уведомление «Расчётное время доставки изменено: 22 окт, 14:30»,
причина — «задержка на маршруте» (без служебных деталей).

## 5. Таблица «боль заказчика → функция» (критерий 6)

| Боль из ТЗ | Функция |
|---|---|
| Диспетчер звонит водителям | Статусы с временем, экран «Внимание» |
| Информация о рейсе в разных местах | Карточка рейса: адреса, контакты, груз, документы в одном месте |
| Клиент не знает, где груз | Таймлайн клиента + уведомления |
| Статус обновляется вручную и устаревает | Статус меняет сам водитель одной кнопкой, realtime |
| Документы теряются в переписке | Документы привязаны к рейсу и этапу |
| Нет истории рейса | `trip_events` — неизменяемый лог |
| Руководитель не видит картину | Дашборд руководителя |

## 6. Дополнительные возможности (критерий 8) — реализуем 3, остальные в «развитие»
Обязательно к показу:
1. **Работа без сети у водителя (outbox).** Статус/фото ставятся в очередь и уходят при появлении сети; индикатор «3 действия ожидают отправки».
2. **Пересчёт планового времени при задержке** + уведомление клиенту с новым ETA.
3. **Экспорт истории рейса в PDF** («Акт выполненного рейса»: события, фото-превью, получатель) — кнопка у диспетчера и клиента.
Если останется время:
4. Центр уведомлений с непрочитанными (уже нужен для сценария).
5. Переключение RU/KZ (i18n уже заложен).
6. Код подтверждения получения (4 цифры клиенту, водитель вводит при выдаче).

«Дальнейшее развитие» (в ролике одним слайдом): GPS, маршруты, push через FCM/APNs,
интеграция 1С, ЭЦП, расчёт стоимости.

## 7. Что клиент НЕ видит
Внутренние комментарии диспетчера, телефон водителя, причины проблем в деталях
(только «задержка на маршруте»), стоимость.
