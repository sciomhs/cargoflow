# AGENTS.md — правила для агентов в этом репозитории

Ты — исполнитель (Codex / ChatGPT). Оркестратор — Claude. Твоя работа — одна задача
из `tasks/backlog.md` за один прогон, от начала до конца, с проверкой.

## Перед началом любой задачи
1. Прочитай `docs/02_product_spec.md`, `docs/03_data_model.md`, `docs/04_design_brief.md`.
2. Прочитай карточку задачи `tasks/T-XX.md` (если файла нет — раздел в `tasks/backlog.md`).
3. Если в репо есть `app/package.json` — стек уже выбран, не меняй его.
4. Если задача про UI — сначала загрузи skill `mobile-taste` (или `mobile-nav-plan` /
   `mobile-design-system` по типу задачи) и следуй его протоколу.

## Стек (фиксирован, см. docs/05_architecture.md)
Expo + Expo Router + TypeScript + NativeWind + Reanimated + Zustand + TanStack Query
+ Supabase (auth, postgres, storage, realtime). Demo-mode на локальных seed-данных.

## Железные правила
- Не создавай GitHub-репозиторий, не делай `git push`, не добавляй remote. Только локальные коммиты.
- Не меняй машину статусов рейса (`docs/03_data_model.md`) без пометки `DECISION NEEDED` в отчёте.
- Весь пользовательский текст — на русском. Деньги — ₸ (тенге). Города — Казахстан.
- Никаких `lorem ipsum`, `John Doe`, `Welcome back!`, эмодзи-иконок, индиго-градиентов,
  5 табов + FAB, бесконечных стопок белых карточек. Полный список запретов —
  `docs/04_design_brief.md` раздел «Запреты».
- Не выдумывай API. Если нужен эндпоинт/таблица, которых нет в `supabase/migrations/` —
  предложи миграцию в отчёте и остановись.
- Каждое изменение статуса рейса пишет событие в `trip_events` с временем. Без исключений.
- Клиент никогда не видит внутренние комментарии диспетчера и телефон водителя.

## Definition of Done для любой задачи
- `npx tsc --noEmit` и `npx expo lint` проходят.
- Экран/фича работает в demo-mode без сети.
- Есть seed-данные, которые показывают состояние «как в ТЗ» (рейс R-642, заказ CF-1845).
- Отчёт в конце прогона по шаблону:
  ```
  ## T-XX: <название>
  Сделано: …
  Файлы: …
  Как проверить: …
  Не сделано / риски: …
  DECISION NEEDED: … (если есть)
  ```
- Один коммит: `T-XX: <что сделано>`.

## Чего НЕ делать
- Не реализовывать GPS-трекинг, карты с маршрутизацией, оплату, 1С, ЭЦП — это вне ТЗ.
- Не добавлять библиотеки «на будущее». Каждая зависимость — по задаче.
- Не переписывать чужие экраны «заодно». Если видишь проблему — в отчёт.
