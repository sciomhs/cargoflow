# CargoFlow: Nav Read (T-02)

Дата: 2026-10-19. Expo SDK 57 / Expo Router 57. Новых зависимостей нет.

## App Read
Рабочий инструмент перевозчика, Android-first; iOS поддерживается, web best-effort.
Характер: дорожный документ. Выразительность 2/5, движение 1/5, плотность диспетчер/водитель/клиент 4/2/3.
Оформление и токены остаются T-03. Заголовки использует стандартный Header из `expo-router/react-navigation`, чтобы выравнивать их слева также на iOS; переходами и стеком управляет Native Stack.

## Jobs и контейнеры
- Повторяемые рабочие разделы: вкладки диспетчера 3, водителя 2, клиента 2 (шаг 1 дерева решений).
- Руководитель возвращается к одному обзору: stack без таббара.
- Рейс, заказ, доставка, проблема, водитель, фото и документы: push (шаг 2).
- Новый заказ, новый рейс, сообщение о проблеме, передача: modal (шаг 3), fullscreen по сценарию полевого ввода и дизайн-брифу.
- Вход: отдельная auth-группа (шаг 5). Настройки: общий push из заголовка (шаг 2).
- Sheets: нет. FAB: нет; создание заказа доступно во вкладке «Заказы», создание рейса в заказе.
- Два таба у водителя и клиента намеренно сохраняются по прямому требованию продукта вопреки общему совету skill избегать двух табов.

## Дерево маршрутов
```text
app/
  _layout.tsx                  роли защищены Stack.Protected
  index.tsx                    redirect на вход / стартовый экран роли
  trip/[id].tsx                служебный role-aware redirect публичной ссылки
  (auth)/
    login.tsx                  вход
  (dispatcher)/                Stack, anchor (tabs)
    (tabs)/                    Tabs: Рейсы · Заказы · Внимание
      trips.tsx
      orders.tsx
      attention.tsx
    trips/[id].tsx             push
    orders/[id].tsx            push
    problems/[id].tsx          push
    orders/new.tsx             fullscreen modal
    trips/new.tsx              fullscreen modal, ?order=<id>
  (driver)/                    Stack, anchor (tabs)
    (tabs)/                    Tabs: Сегодня · История
      today.tsx
      history.tsx
    trips/[id]/                Stack, anchor index
      index.tsx                push: Рейс
      photo.tsx                push
      docs.tsx                 push
      problem.tsx              fullscreen modal
      handover.tsx             fullscreen modal
  (client)/                    Stack, anchor (tabs)
    (tabs)/                    Tabs: Доставки · Уведомления
      deliveries.tsx
      notifications.tsx
    deliveries/[id].tsx        push
  (manager)/                   Stack, anchor dashboard
    dashboard.tsx
    drivers/[id].tsx           push
  settings.tsx                 общий protected push
```

22 экрана ТЗ; index и trip/[id] не считаются экранами продукта. Детали и модальные окна находятся вне (tabs), поэтому после завершения перехода таббар закрыт. Вложенных таббаров нет, у экрана один владелец заголовка.

## Входы, возврат и URL
Префикс всех внешних ссылок: `cargoflow://`. Группы `(role)` и `(tabs)` используются во внутренних typed Href и не добавляют сегментов публичному URL.

| Экран | Откуда | Назад / Отмена | URL после префикса |
|---|---|---|---|
| Вход | запуск без роли; «Сменить роль» | старт приложения | login |
| Диспетчер: Рейсы | вход, таб | выход приложения | trips |
| Диспетчер: Заказы | таб | Рейсы, затем выход | orders |
| Диспетчер: Внимание | таб | Рейсы, затем выход | attention |
| Диспетчер: Рейс | Рейсы | выбранный таб | trip/:id (role-aware alias) |
| Диспетчер: Заказ | Заказы | Заказы | orders/:id |
| Диспетчер: Проблема | Внимание | Внимание | problems/:id |
| Новый заказ | Заказы → Создать заказ | Заказы | orders/new |
| Новый рейс | Заказ → Создать рейс | Заказ | trips/new?order=:id |
| Водитель: Сегодня | вход, таб | выход приложения | today |
| Водитель: История | таб | Сегодня, затем выход | history |
| Водитель: Рейс | Сегодня или История | исходный таб | trip/:id (role-aware alias) |
| Фото рейса | Рейс | Рейс | trips/:id/photo |
| Документы | Рейс | Рейс | trips/:id/docs |
| Сообщить о проблеме | Рейс | Рейс | trips/:id/problem |
| Передача груза | Рейс | Рейс | trips/:id/handover |
| Клиент: Доставки | вход, таб | выход приложения | deliveries |
| Клиент: Уведомления | таб | Доставки, затем выход | notifications |
| Доставка | Доставки или Уведомления | исходный таб | deliveries/:id |
| Обзор руководителя | вход | выход приложения | dashboard |
| Рейсы водителя | Обзор | Обзор | drivers/:id |
| Настройки | значок в заголовке рабочего раздела | исходный экран | settings |

При прямом открытии деталей anchor добавляет под ними стартовый экран роли. Для вложений водителя anchor index дополнительно даёт родительский рейс. Из Истории обычный push/back сохраняет Историю; из Уведомлений клиента сохраняет Уведомления.

`cargoflow://trip/R-642` маршрутизируется в детали диспетчера/водителя или доставку клиента. У руководителя отдельный экран рейса не предусмотрен: ссылка возвращает его в Обзор. Без роли alias передаёт id через login?trip=..., после выбора роли открывается нужный экран с anchor. Идентификатор остаётся параметром, а не частью вручную собранной строки маршрута.

В Expo Go эквивалент: `exp://127.0.0.1:8081/--/trip/R-642`. Custom scheme проверяется уже в установленной сборке; Expo Go использует свой exp://.

Другие protected deep links открываются только при уже выбранной подходящей роли; без роли защита отправляет на вход, а восстановление произвольного целевого адреса после входа пока не реализовано. Это ограничение текущего demo-входа; сохранение назначения сейчас реализовано для публичного alias trip/:id.

## Android back и незавершённый ввод
- Обычные экраны: стандартный pop, совпадающий с кнопкой «Назад». У табов сохранён стандартный backBehavior firstRoute: сначала возврат на первую вкладку, затем выход Android на корне стека.
- Модальные маршруты: видимая «Отмена», стандартный Android back. На iOS свайп закрытия отключён, чтобы будущая форма не теряла ввод случайно.
- В T-02 формы пустые: закрытие сразу возвращает к вызывающему экрану, сохранять нечего.
- В T-08/T-11/T-13 формы с изменёнными полями должны перехватывать удаление маршрута общим guard: «Отменить изменения?» → «Продолжить ввод» / «Отменить изменения». Один guard покрывает «Отмена», hardware/gesture back и смену роли; до реализации такого guard ввод в этих маршрутах не добавлять.
- Отдельного BackHandler в T-02 нет.

## Самопроверка и изменения относительно T-01
- Порядок и подписи табов сохранены; их прежние публичные адреса сохранены.
- Внутренние href стартовых экранов уточнены добавлением (tabs); index использует общий homeRoutes.
- Добавлены 12 деталей/задач, общие настройки и служебный alias. Все 22 экрана достижимы через UI.
- Основные детали: 1 тап от рабочего раздела. Создание рейса и вложения: 2 тапа. Фото/документы/проблема/передача из таба История или Сегодня доступны за 2 тапа.
- Ссылки на экраны пока используют preview, не создавая бизнес-данные. CF-1845 и R-642 отсутствуют в seed; публичный alias лишь передаёт id и ничего не создаёт.
- Полноэкранные модалки не содержат вложенных push. Дублированных заголовков и Settings/Logout-табов нет.
