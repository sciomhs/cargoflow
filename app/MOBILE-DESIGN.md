# CargoFlow: MOBILE-DESIGN

Дата: 2026-10-19. Источник: docs/04_design_brief.md. Реализация: T-03.

## App Read
Рабочий инструмент перевозчика: диспетчерская, склад, кабина. Характер дорожного документа задают строки, IBM Plex и точные числовые подписи.
Android-first, iOS поддерживается, web best-effort. Единый визуальный язык, стандартные навигаторы Expo Router.

## Nav Read
Карта и deep links зафиксированы в NAV.md. Табы: диспетчер 3, водитель 2, клиент 2, руководитель без таббара. Детали закрывают таббар, задачи создания используют fullscreen modal. Настройки доступны из заголовка.
Для разработки: Настройки → Галерея компонентов; группа (dev) закрыта через Stack.Protected при __DEV__=false. Галерея не является экраном продукта и не меняет 22 экрана ТЗ.

## Дилы
- Выразительность 2/5: характер даёт типографика, без декоративных элементов.
- Движение 1/5: переходы навигатора и обратная связь нажатия; без декоративных анимаций.
- Плотность диспетчер/водитель/клиент 4/2/3: у водителя строка минимум 56 и больше вертикальный отступ; остальные строки минимум 48.

## SAFE / RISK
SAFE: тёплый нейтральный фон, один зелёный акцент, стандартная навигация, простые разделители и крупные цели нажатия поддерживают рабочий сценарий.

RISK 1: IBM Plex Mono для номеров, массы, времени и денег.
Выигрыш: числа проще сравнивать; цена: две гарнитуры надо загрузить до splash hide. Используются пакетные TTF, без Google Fonts-запросов при запуске.

RISK 2: отдельная ночная тема водителя.
Выигрыш: меньше яркого света в кабине; цена: второй набор цветов и отдельная проверка контраста. Ночной режим включается только у водителя при тёмной теме системы; у остальных ролей светлый.

RISK 3: радиус 6 и отсутствие теней.
Выигрыш: ощущение документа; цена: иерархию надо строить типографикой, отступами и линиями. Ровная поверхность не заменяется стопкой карточек.

Проверка согласованности: зелёный #1F6F4A сохраняется у залитой кнопки в обеих темах; мелкие зелёные подписи и активные табы ночью используют более светлый оттенок той же цветовой семьи ради контраста. Цвет статуса передаётся точкой и подписью, не только цветом.

## Design System
Источник значений: src/ui/tokens.ts. React-компоненты получают цвета через src/ui/theme.tsx; NativeWind использует vars() и семантические цвета tailwind.config.js. Тест проверяет совпадение цветов, шрифтов, шкалы и радиуса в обоих слоях.

| Токен | Светлая | Тёмная | Почему |
|---|---|---|---|
| background | #F4F2EE | #141311 | тёплая основа без холодного серого |
| surface | #FFFFFF | #1E1C19 | поля и вторичные кнопки отделяются от основы |
| text | #1A1917 | #F4F2EE | контрастный основной текст |
| muted | #5E5A54 | #B7B0A6 | вторичные подписи сохраняют читаемость |
| border | #DCD8D0 | #443F38 | спокойные разделители |
| pressed | #E9E5DD | #2A2722 | обратная связь строки без тени |
| accent | #1F6F4A | #1F6F4A | один основной зелёный |
| accentText | #1F6F4A | #8ABF9E | читаемый зелёный текст и активный таб |
| onAccent | #FFFFFF | #FFFFFF | контраст на основной кнопке |
| destructive | #B4411F | #B4411F | действие удаления отличается от основного |
| onDestructive | #FFFFFF | #FFFFFF | контраст на destructive-кнопке |
| delay | #B4411F | #E79479 | задержка и ошибка поля |
| waiting | #8A6D1F | #D5B45F | точка ожидания |
| completed | #4E7A5F | #91B19A | точка завершённого этапа |

Основной, вторичный текст, accentText, текст ошибки и подписи залитых кнопок проверяются тестом на контраст ≥4,5:1. Точки статусов проверяются на ≥3:1. Охра и завершённый зелёный не используются для мелкого текста на светлом фоне: подпись StatusChip остаётся основным цветом текста.

## Типографика и размеры
- Sans: IBM Plex Sans 400; акцент подписи: IBM Plex Sans 500; Mono: IBM Plex Mono 400 с tabular-nums.
- Caption 12/16, small 14/20, body 16/24, title 20/28, display 28/36. Числа display моноширинные, заголовки regular.
- Body масштабируется без ограничения; кнопки и собственные элементы chrome ограничены множителем 1,3. Высоты являются минимальными и не обрезают масштабированный текст.
- Шаг отступов 4: 4 / 8 / 12 / 16 / 24 / 32; стандартный горизонтальный отступ 16.
- Цели нажатия 48, водитель 56, driver-xl 64. Footer водителя должен учитывать SafeArea у вызывающего экрана.
- Радиус кнопки и поля 6; точки статуса круглые 8×8 и не являются контейнерами.
- Иконки только Lucide 20, stroke 1,75; иллюстрации и эмодзи не используются.
- Elevation: плоские поверхности; тени и дополнительные уровни не вводятся.

## Компоненты
| Компонент | Контракт | Почему |
|---|---|---|
| Text | size, tone, mono, medium + TextProps | общая типографика и числовой шрифт |
| Button | label, hint?, variant + PressableProps | primary / secondary / destructive / driver-xl, disabled и press feedback |
| Row | label, detail?, detailMono?, trailing?, selected? + PressableProps | строки с разделителем; статическая строка не выглядит кнопкой |
| StatusChip | label, tone | текст и семантическая точка без цветной капсулы |
| Timeline | steps с id, label, time?, state | ограниченный список этапов, вертикальная линия и моно-время |
| Field | label, error? + TextInputProps | видимая подпись, фокус, disabled и ошибка с alert |
| EmptyState | label, action? | одна строка и одно действие без иллюстраций |
| Skeleton | две статичные строки | показывает форму загрузки без спиннера и бесконечного shimmer |

Timeline предназначен для ограниченного набора этапов рейса, не для бесконечного event feed. Бесконечные списки и ленты событий в следующих задачах используют FlatList.

Field получает keyboardType и autoComplete/textContentType от конкретного поля. В галерее получатель имеет name/name/default. Валидация бизнес-данных остаётся у формы; примитив показывает переданную ошибку.

NativeWind v4 не сохраняет Pressable style callbacks: у Button, интерактивного Row и смены роли применяется cssInterop=false, так как их стили вычисляются из общих токенов напрямую. Стили остальных компонентов и переменные NativeWind продолжают работать.

## Движение, состояния и доступность
Нажатие кнопки меняет прозрачность, нажатие строки меняет фон. Skeleton статичен, поэтому отдельная анимация при reduced motion не требуется. Haptics не добавлялись: навигационные нажатия не должны вибрировать, библиотека не нужна для T-03.

Button и Row объявляют роль, label и выбранное/disabled-состояние. Timeline озвучивает пройденный, текущий и будущий этап. Skeleton объявляет загрузку, Field связывает подпись и озвучивает ошибку. SafeArea остаётся у экрана и footer.

Галерея: app/(dev)/ui-gallery.tsx. Представлены все 8 компонентов, варианты Button, disabled, выбор Row, проверка пустого/заполненного Field и переключение светлого/тёмного образца. Эти примеры не создают заказы, рейсы или seed-данные; счётчик нажатий относится только к галерее. Переключатель меняет область образцов; заголовок сохраняет тему текущей роли.

## Запреты и границы
Нет градиентов, фиолетового, теней, карточных стопок, FAB, приветствий и выдуманных бизнес-данных. Ровно один характерный приём: IBM Plex Mono на числовых данных.
T-03 не подключает Supabase, не меняет статусы рейса и не реализует бизнес-формы.
